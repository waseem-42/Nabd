# دليل العمل المشترك على نبض (GitHub + Claude Code)

المستودع: https://github.com/waseem-42/Nabd (خاص)

> **مهم:** لا توجد مزامنة تلقائية بين الأجهزة. أي تعديل لا يصل للطرف الثاني إلا بعد
> `commit` ثم `push` من جهازك، ثم `pull` من جهازه.

---

## 1) أول مرة على جهاز جديد

```bash
gh auth login                 # تسجيل الدخول لحساب GitHub (مرة واحدة)
gh repo clone waseem-42/Nabd
cd Nabd
npm install
npm run dev                   # تشغيل الموقع محليًا
```

إعداد هويتك في Git (مرة واحدة لكل جهاز):

```bash
git config --global user.name  "اسمك"
git config --global user.email "بريدك في GitHub"
```

---

## 2) القاعدة الذهبية: لا تعدّل على `main` مباشرة

- `main` = النسخة المعتمدة والمستقرة.
- كل تعديل يكون في **فرع مستقل** ثم **Pull Request** يراجعه الطرف الثاني قبل الدمج.
- أسماء الفروع: `feat/وصف-قصير` لميزة، `fix/وصف-قصير` لإصلاح، `docs/...` للتوثيق.
  مثال: `feat/workout-timer`، `fix/rtl-header`.

---

## 3) دورة العمل اليومية

### أ) قبل ما تبدأ: اسحب آخر التحديثات

```bash
git switch main
git pull
```

### ب) افتح فرعًا جديدًا لتعديلك

```bash
git switch -c feat/اسم-التعديل
```

### ج) اشتغل واحفظ (commit) على دفعات صغيرة

```bash
git status                    # شوف وش تغيّر
git add <الملفات>
git commit -m "وصف واضح للتعديل"
```

### د) تأكد أن المشروع يبني بدون أخطاء

```bash
npm run build
npm test
```

### هـ) ارفع الفرع وافتح Pull Request

```bash
git push -u origin feat/اسم-التعديل
gh pr create --fill --base main
```

### و) المراجعة والدمج

- الطرف الثاني يراجع: `gh pr list` ثم `gh pr view <رقم>` أو من صفحة GitHub.
- لتجربة فرع زميلك على جهازك: `gh pr checkout <رقم>` ثم `npm install && npm run dev`.
- الدمج يتم **يدويًا** بعد الموافقة: `gh pr merge <رقم> --squash --delete-branch`
  (الدمج التلقائي غير مفعّل).
- بعد الدمج، الكل يرجع ويحدّث: `git switch main && git pull`.

---

## 4) استقبال تحديثات زميلك

```bash
git switch main
git pull                      # يجلب كل ما دُمج في main
npm install                   # إذا تغيّر package.json
```

إذا كنت في منتصف فرعك وتبي آخر تحديثات `main` داخله:

```bash
git switch feat/فرعي
git merge main
```

---

## 5) تجنّب التعارضات (Conflicts)

1. **اسحب قبل ما تبدأ** (`git pull` على `main`) كل يوم.
2. **فروع قصيرة العمر:** ادمج خلال يوم أو يومين بدل فرع ضخم لأسبوع.
3. **نسّقوا من يشتغل على أي ملف** — خصوصًا الملفات الكبيرة المشتركة مثل
   `src/data/*` و`public/art/*` وملفات الترجمة `src/i18n/*`.
4. **لا تعدّل `package-lock.json` يدويًا**؛ ثبّت الحزم بـ `npm install <حزمة>` فقط.
5. **commits صغيرة وواضحة** أسهل في المراجعة وفي حل التعارض.

### إذا ظهر تعارض

```bash
git status                    # يعرض الملفات المتعارضة
```

افتح الملف، ستجد علامات `<<<<<<<` و`=======` و`>>>>>>>`. اختر الصحيح (أو ادمج
الاثنين)، احذف العلامات، ثم:

```bash
git add <الملف>
git commit
```

أو اطلب من Claude Code: «فيه تعارض بعد الدمج، ساعدني أحله بدون ما تضيّع تعديلات أي طرف».

### ممنوعات

- `git push --force` على `main` أو على فرع زميلك.
- `git reset --hard` أو حذف ملفات لا تعرف مصدرها.
- رفع ملفات `.env` أو أي مفاتيح/كلمات مرور (مستثناة في `.gitignore`).

---

## 6) العمل باستخدام Claude Code

كل شخص يشغّل Claude Code على جهازه داخل مجلد المشروع. ملف `CLAUDE.md` في جذر المشروع
يعطي Claude نفس قواعد العمل عند الطرفين تلقائيًا. أمثلة طلبات مفيدة:

| تبي | قل لـ Claude Code |
|---|---|
| تبدأ يومك | «اسحب آخر تحديثات main» |
| تبدأ تعديل | «افتح فرع جديد feat/... وابدأ في ...» |
| ترسل شغلك | «اعمل commit للتعديلات وارفع الفرع وافتح Pull Request» |
| تراجع شغل زميلك | «اعرض Pull Requests المفتوحة وراجع رقم ...» |
| تجرب شغل زميلك | «اعمل checkout للـ PR رقم ... وشغّل المشروع» |
| تدمج بعد الموافقة | «ادمج PR رقم ... بـ squash واحذف الفرع» |
| تستقبل تحديثاته | «ارجع لـ main واسحب التحديثات وثبّت الحزم إذا تغيّرت» |
